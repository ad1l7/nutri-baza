# Блюда из O·ERP вместо iiko

Olive переходит с iiko на O·ERP как источник блюд. Код: `myapp/oerp_sync.py`,
команда `manage.py oerp_sync`. Исходное ТЗ — `olive-iz-oerp.md` в проекте O·ERP
(`.claude/docs/handoff/api/`), формат API сверен с кодом O·ERP (`origin/main`,
модуль `public-api`) 09.11.2026.

## Откуда что берётся

| Поле Olive | O·ERP |
|---|---|
| список блюд, категория | `export/groups` → подпапки «ЗДОРОВОЕ ПИТАНИЕ»; `export/products?kind=dish` и `?kind=goods` с `groupId` в этих папках |
| `iiko_id` | `id` (для перенесённых из iiko — тот же GUID) |
| `article` | `code` |
| `name` | `name` |
| `iiko_category` | имя папки без цифры порядка («1ПП* ЗАВТРАК» → «ПП* ЗАВТРАК») |
| `packing` | `baseUomName` |
| `net_weight` | `unitWeightKg` (кг), до целого грамма |
| КБЖУ на 100 г | `nutrition.per100g` (`kcal`, `protein`, `fat`, `carbs`) |
| КБЖУ на порцию, кДж | считаются в Olive, как раньше |
| `composition` | `export/tech-cards?date=сегодня` (все карты одним списком), раскрытие до сырья тем же алгоритмом, что у iiko; фолбэк — `description` |
| `cost` | `export/dish-costs?date=сегодня` (+ `kind=goods` для товаров), поле **`ssc`** (ССС). `null` — «не посчитано», старое значение остаётся |
| `photo` | в O·ERP нет — скачанные остаются, новые грузить в админке |

Категория папки определяется той же картой, что у iiko (`IikoCategoryMap` в
админке + встроенные названия). При сравнении отбрасываются цифра порядка,
регистр, пробелы и «ккал», поэтому «ПП* ДОП.ТОВАРЫ» совпадает с
«ПП* Доп. товары». Вложенные подпапки наследуют категорию родителя.
Папки без категории (ФМД, MAGNUM CHEF) не загружаются.

Отличие от ТЗ: там поле себестоимости названо `sss`, а в API оно `ssc`.
Код читает `ssc`, а если его нет — `sss`.

## Переключение

1. Получить у администратора O·ERP ключ `erpk_…` (право `S_API` или
   `ERP_EXPCOST`) и добавить в `~/nutri-baza/.env` на сервере Olive:
   ```
   OERP_API_KEY=erpk_...
   ```
2. Сверка — скачивает из O·ERP и сравнивает с базой, ничего не пишет:
   ```
   cd ~/nutri-baza && venv/bin/python manage.py oerp_sync --compare
   ```
   Показывает: сколько блюд нашлось, новые и пропавшие, расхождения по
   названию, артикулу, весу, КБЖУ, составу и себестоимости (числа — до 2 знаков).
3. Когда расхождения объяснены — переключить кнопку синхронизации в каталоге:
   ```
   PRODUCT_SOURCE=oerp
   ```
   в `.env` и перезапустить службу (`~/deploy.sh` или `sudo systemctl restart olive`).
   Разовая загрузка из консоли: `manage.py oerp_sync --apply`.
4. После того как загрузка из O·ERP поработает — удалить код iiko
   (`iiko_sync.py`, вызовы в `views.py`) и восемь переменных `IIKO_*`
   из `.env` и `settings.py`.

Блюда, пропавшие из папок O·ERP, не удаляются — только пишутся в лог,
как и при загрузке из iiko.
