# Каталог блюд из iiko — передача проекта

Django-приложение, которое тянет блюда из iiko и показывает их каталогом:
КБЖУ, состав, масса, себестоимость, цена продажи, фото, фильтры, выгрузка в Excel.

Этот документ написан для переноса **только вкладки «Каталог»** в новый продукт.
Всё, что касается рационов, калоражей и блюд на замену, помечено как лишнее —
в разделе «Что выбросить» указано, какие файлы и модели удалять и в каком порядке.

---

## 1. Стек и требования

| | |
|---|---|
| Python | 3.12 |
| Django | 5.0.14 |
| БД | PostgreSQL (прод), SQLite (локально, флаг `USE_SQLITE=True`) |
| Веб-сервер | gunicorn + systemd |
| Внешние сервисы | iiko Cloud API (`api-ru.iiko.services`), iiko Server (`/resto/api`) |

Зависимости — в `requirements.txt`. Для каталога обязательны: `Django`,
`python-decouple`, `requests`, `openpyxl`, `Pillow`, `psycopg2-binary`.
`anthropic` и `django-filter` нужны только рационам, их можно выкинуть.

## 2. Быстрый старт

```bash
python -m venv venv
venv/Scripts/activate          # Windows; на Linux: source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env           # заполнить значения, см. раздел 3
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Каталог открывается на `/`, вход — `/login/`, админка — `/admin/`.
Без входа приложение не отдаёт ни одну страницу: этим занимается
`LoginRequiredMiddleware`.

## 3. Переменные окружения

Всё читается через `python-decouple` из `.env` (файл в `.gitignore`).
`SECRET_KEY` и все `IIKO_*` заданы **без значений по умолчанию** — если
переменной нет, приложение не стартует.

| Переменная | Зачем | Где взять |
|---|---|---|
| `SECRET_KEY` | Django | сгенерировать |
| `DEBUG` | режим отладки | `False` на проде |
| `USE_SQLITE` | локальная БД вместо PostgreSQL | задать `True` локально |
| `DB_NAME`, `DB_USER`, `DB_PASSWORD` | PostgreSQL | ваша БД |
| `IIKO_CLOUD_API_KEY` | apiLogin для старой авторизации | iikoweb, раздел API |
| `IIKO_APP_ID`, `IIKO_CLIENT_SECRET` | новая авторизация Cloud API | кабинет разработчика iiko |
| `IIKO_ORG_ID` | организация | Cloud API, `/api/1/organizations` |
| `IIKO_EXTERNAL_MENU_ID` | внешнее меню | iikoweb, раздел «Внешние меню» |
| `IIKO_SERVER_URL` | `https://ваш-сервер.iiko.it/resto` | iiko Server |
| `IIKO_SERVER_LOGIN`, `IIKO_SERVER_PASSWORD` | учётка iiko Server | администратор iiko |
| `ANTHROPIC_API_KEY` | только для рационов | не нужен, если берёте один каталог |

Хосты и CSRF прописаны прямо в `myproject/settings.py` (`ALLOWED_HOSTS`,
`CSRF_TRUSTED_ORIGINS`) — поменяйте под свой домен.

## 4. Откуда берутся данные

Вся синхронизация — в `myapp/iiko_sync.py`, функция `sync_products_from_iiko`.
Запускается кнопкой «Обновить из iiko» в каталоге (`POST /iiko/sync/`).
Работают **два разных API iiko**, у них разные адреса и авторизация.

### 4.1. iiko Cloud API — что за блюда и их КБЖУ

`https://api-ru.iiko.services`, токен на час.

| Эндпоинт | Что даёт |
|---|---|
| `POST /api/2/access_token` | токен по `appId` + `clientSecret` (новый способ) |
| `POST /api/1/access_token` | токен по `apiLogin` (старый, iiko его отключает) |
| `POST /api/2/menu/by_id` | **внешнее меню**: состав позиций, категории, КБЖУ, вес, фото, артикулы |
| `POST /api/1/nomenclature` | номенклатура доставки; у нас почти бесполезна, см. грабли |

Разбор меню — `_extract_menu_items`. Нюансы, которые уже отлажены:

- `nutritionPerHundredGrams` приходит то объектом, то списком — берём первый;
- кДж в iiko нет, считаем `ккал × 4.184`;
- «на порцию» в iiko нет, считаем `на 100 г × вес / 100`;
- одно блюдо может лежать в нескольких категориях — дубли не создаём;
- артикул ищем в `sku`/`code` на позиции или на размере.

### 4.2. iiko Server — название, состав и себестоимость

`https://<сервер>.iiko.it/resto/api`, ключ сессии выдаёт `GET /api/auth`.
**Обязательно вызывать `GET /api/auth/logout`** — число одновременных сессий
ограничено, забытые ключи блокируют следующие синхронизации.

| Эндпоинт | Что даёт |
|---|---|
| `GET /api/v2/entities/products/list` | «Название в системе», артикул, описание |
| `GET /api/v2/assemblyCharts/getTree` | техкарта блюда → состав |
| `POST /api/v2/reports/olap` | OLAP-отчёт → себестоимость |

**Название.** Берём из `products/list`, а не из внешнего меню: во внешнем меню
имя редактируется отдельно и часто скопировано с соседней позиции. Связка —
по `itemId` меню = `id` продукта, запасная — по совпадающему уникальному артикулу.

**Состав.** `getTree`, а не `getPrepared`: prepared-карта не заходит в
полуфабрикаты со списанием DIRECT и теряет их ингредиенты. Дерево раскрываем
сами до конечного сырья (`_tree_leaves`, `_composition_from_tree`):

- у продукта бывает несколько карт с разными периодами — берём действующую;
- количества перемножаются по дереву, сортировка по убыванию массы: на этикетке
  ингредиенты обязаны идти от основного к второстепенному;
- запросов много (по одному на блюдо), поэтому они идут пулом из 8 потоков —
  последовательно ~290 запросов не укладываются в таймаут веб-сервера.

**Себестоимость.** OLAP-отчёт `TRANSACTIONS` за последние `COST_HISTORY_DAYS`
(60) дней: тип транзакции `OUTGOING_INVOICE`, группа номенклатуры
«ЗДОРОВОЕ ПИТАНИЕ», разбивка по учётному дню и продукту. Цена за единицу =
`Sum.Incoming / Amount.Out`, берётся последняя ненулевая. Сопоставление —
по GUID продукта, затем по артикулу. См. грабли в разделе 8, там много крови.

**Фото.** URL из внешнего меню, скачивается только если сменился (сравнение по
md5 от URL в имени файла).

### 4.3. Что синхронизация делает с базой

- Блюдо ищется по артикулу → `iiko_sku` → `iiko_id`. По артикулу — потому что
  при пересоздании карточки в iiko меняется её внутренний код, а артикул живёт.
- Новые блюда создаются, существующие обновляются только при реальном изменении
  полей (`_COMPARE_FIELDS`).
- **Автоудаление отключено намеренно**: пропавшие из меню блюда остаются в базе,
  в лог пишутся кандидаты. Иначе терялись блюда, на которые ссылались рационы.
- Категория блюда ставится по названию категории iiko через таблицу
  соответствий `IikoCategoryMap` (правится в админке, без правки кода).
- Ограничения: не чаще одного запуска в `MIN_SYNC_INTERVAL` секунд и не больше
  `IikoSyncLog.DAILY_LIMIT` раз в сутки (сейчас 1000 — поднято для отладки,
  для боевой работы верните 5–10).

## 5. Модель каталога

`myapp/models.py`, класс `Product` — единственная модель, которая действительно
нужна каталогу. Плюс `MealCategory` (категории блюд), `IikoCategoryMap`
(соответствие категорий iiko → свои) и `IikoSyncLog` (лог и лимит синхронизаций).

| Поле | Откуда |
|---|---|
| `name` | iiko Server, «Название в системе» |
| `article` | внешнее меню, фолбэк — номенклатура |
| `photo` | внешнее меню, файл скачивается в `media/products/` |
| `cost` | OLAP-отчёт себестоимости |
| `sale_price`, `sale_price_manual` | считается из `cost`, либо вводится руками |
| `net_weight` | внешнее меню, `portionWeightGrams` (в базе в кг) |
| `packing` | внешнее меню, `measureUnit` |
| `composition` | техкарта iiko, как есть |
| `composition_clean` | то же через справочник ингредиентов, пересчитывается в `save()` |
| КБЖУ на 100 г и на порцию | внешнее меню, порционные — расчётные |
| `meal_categories` | категория внешнего меню через `IikoCategoryMap` |
| `iiko_id`, `iiko_sku`, `iiko_category`, `iiko_synced_at` | служебные, для сопоставления |

### Цена продажи

`Product.save()` держит наценку `MARKUP_TARGET_PCT` (67%) от себестоимости и
округляет вверх до целых тенге. Если цену ввели руками, ставится
`sale_price_manual=True` и автопересчёт прекращается; пустое поле возвращает
автоматический режим. При нулевой себестоимости цена не трогается — ноль
считается отсутствием данных, а не бесплатным блюдом. Наценка ниже
`MARKUP_MIN_PCT` (40%) подсвечивается в интерфейсе.

### Состав и справочник ингредиентов

`myapp/ingredient_aliases.py` — словарь на ~350 строк: приводит ингредиенты из
техкарт к человеческому виду (убирает артикульные хвосты, склеивает синонимы,
выкидывает воду и служебные позиции). Результат — в `composition_clean`, именно
он показывается везде. Команда `python manage.py unknown_ingredients` печатает
ингредиенты, которых нет в справочнике, — так он и пополняется.

## 6. Роли и права

- Обычный пользователь — полный доступ.
- **Читатель** — состоит в группе `readers`: видит всё, но любой изменяющий
  запрос блокируется в `ReaderReadOnlyMiddleware` на уровне бэкенда, а не
  прятаньем кнопок.
- Точечные разрешения читателю — модель `UserRights`, галочки в карточке
  пользователя в админке: «Может менять цены продажи» (только поле цены в
  каталоге) и «Может вести рационы Claude» (нужно лишь рационам).

Если оставляете один каталог — нужны `roles.py`, `middleware.py`,
`context_processors.py` и `UserRights`, но из `roles.py` можно выкинуть все
функции с `claude` в названии.

## 7. Что выбросить, если нужен только каталог

Каталог не зависит ни от рационов, ни от замен, ни от калоражей — связь
односторонняя, поэтому удаление безопасно. Порядок действий:

**1. Шаблоны** — удалить `myapp/templates/myapp/`:
`calorie_list.html`, `claude_group_list.html`, `claude_ration_edit.html`,
`group_detail.html`, `material_list.html`, `swap_list.html`.
Остаются `product_list.html` (каталог) и `login.html`.

**2. Маршруты** — в `myapp/urls.py` оставить только:

```python
path("", views.product_list, name="product_list"),
path("export/", views.product_export, name="product_export"),
path("product/<int:pk>/card/", views.product_card, name="product_card"),
path("product/<int:pk>/sale-price/", views.product_set_sale_price, name="product_set_sale_price"),
path("iiko/sync/", views.iiko_sync_view, name="iiko_sync"),
path("iiko/status/", views.iiko_sync_status, name="iiko_sync_status"),
```

**3. Вьюхи** — в `views.py` оставить: `get_filtered_products`, `product_list`,
`product_export`, `product_card`, `product_set_sale_price`, `iiko_sync_view`,
`iiko_sync_status`. Удалить всё, что связано с рационами, заменами, калоражами,
материалами и заявочным листом. Шаблонные фильтры
`myapp/templatetags/custom_filters.py` (`smart_num`, `get_item`, `multiply`)
каталогу нужны — не трогайте.

**4. Модели** — удалить `Ration`, `RationGroup`, `RationSlot`,
`ClaudeRationGroup`, `ClaudeRation`, `ClaudeRationSlot`, `SwapGroup`,
`SwapItem`, `CalorieCategory`, `CalorieCategoryMeal`, `MealTime`, `Material`,
`Allergen` (уже не используется). Оставить `Product`, `MealCategory`,
`IikoCategoryMap`, `IikoSyncLog`, `UserRights`.
После правки — `python manage.py makemigrations && python manage.py migrate`.

**5. Файлы целиком** — `myapp/claude_rations.py`,
`myapp/management/commands/clone_ration_groups.py`,
`myapp/management/commands/copy_rations_to_claude.py`, а заодно
`myapp/filters.py` — он мёртвый и ссылается на поля, которых в модели нет
(`kcal_100`, `category`); вместе с ним уходит зависимость `django-filter`.

**6. Синхронизация** — в `iiko_sync.py` подчистить: защиту от удаления блюд,
занятых в рационах (`RationSlot`, `SwapItem` в шаге 5), и, если категории
блюд не нужны, весь блок `_build_label_to_key` / `_pick_category`.

**7. Навигация** — в `product_list.html` убрать ссылки на удалённые вкладки
(поиск по `nav-tab`).

Проще всего резать в этом порядке и после каждого шага запускать
`python manage.py check` — он ловит битые импорты и ссылки.

## 8. Грабли, на которые мы уже наступили

Самое ценное в этом документе. Каждый пункт стоил отладки на живых данных.

**Нулевая себестоимость затирала нормальную.** В OLAP-отчёте строки с
`Sum.Incoming = 0` — это списание с нулевого остатка (производство не
проводилось), а не бесплатное блюдо. Раньше такие строки писались в каталог
нулём и затирали прежнюю цену: 101 блюдо из 289 встало в ноль. Теперь строки с
нулевой суммой пропускаются.

**Окно отчёта в один месяц.** Если считать себестоимость за текущий месяц, то
первого числа окно равно одному дню, и покрытие рушится. Берём 60 дней и
последнюю ненулевую цену по учётному дню.

**Фильтр по контрагенту.** Отчёт был завязан на контрагента «0Частное лицо
Покупатель». По нему месяцами не было ни одной отгрузки, отчёт приходил пустым,
и себестоимость просто не обновлялась — это выглядело как «всё работает».
Потом по этому контрагенту провели техническую накладную на 287 позиций по 1 шт
с нулевой ценой, и каталог обнулился. Фильтр по контрагенту убран.

**Сопоставление по названию.** Раньше себестоимость искалась в том числе по
имени блюда, с отбрасыванием хвоста `(1порц)`. Из-за этого «Поке с лососем»
отдавал свою цену «Поке боул с уткой» — во внешнем меню у них было одинаковое
имя. Поиск по названию убран совсем: GUID и артикул закрывают все совпадения.

**Cloud-номенклатура почти пустая.** `/api/1/nomenclature` отдаёт только меню
доставки: 85 позиций против 289 во внешнем меню, пересечение по uuid — ноль.
Ни названия, ни артикулы оттуда брать нельзя, источник — iiko Server.

**Накладные выписывают на завтра.** Верхняя граница периода в OLAP должна быть
`сегодня + 2 дня`: `includeHigh` у фильтра выключен, и с `+1` завтрашний
учётный день в отчёт не попадает.

**Группировка по дате.** Поле `DateTime.OperDayFilter` годится только для
фильтра; для группировки нужно `DateTime.DateTyped`, иначе API отвечает
`Grouping is not allowed`.

**Авторизация Cloud API.** `POST /api/2/access_token` может отвечать 401, если
`appId`/`clientSecret` протухли, — тогда код молча падает на старый
`/api/1/access_token`, который iiko отключает. Проверяйте, каким способом
реально получен токен.

**Токен iiko Server.** Всегда делайте logout, даже при исключении. Иначе сессии
кончатся и синхронизация начнёт падать на авторизации.

**Себестоимость есть не у всех.** Блюда, которые ещё ни разу не производили и
не отгружали, не имеют себестоимости нигде — ни в накладных, ни в актах
приготовления. Это нормально: показывайте прочерк, а не ноль.

## 9. Выгрузка в Excel

`product_export` отдаёт каталог с учётом применённых фильтров: категория,
наименование, артикул, кратность, масса, себестоимость, КБЖУ на 100 г и на
порцию, состав. Делается на `openpyxl`, стили заданы руками, имя файла — с
кириллицей через `quote`. Хороший образец, если нужны другие выгрузки.

## 10. Деплой

Автодеплоя нет. На сервере: `git pull` → `pip install -r requirements.txt` →
`manage.py migrate` → `manage.py collectstatic` → рестарт gunicorn. Статика
собирается в `staticfiles/`, медиа лежит в `media/` и раздаётся Django только
при `DEBUG=True` — на проде отдавайте её nginx.

## 11. Чего в архиве нет

- `.env` — секреты. Шаблон: `.env.example`.
- `db.sqlite3` — база с данными.
- `venv/` — окружение, ставится из `requirements.txt`.
- `media/` — фото блюд (11 МБ), скачаются сами при первой синхронизации.
- `.git/` — история репозитория.

Файл `docs/erp-iiko-direct.md` оставлен: это разбор прямой работы с iiko,
писался для смежной системы, там детали по эндпоинтам и форматам ответов.
